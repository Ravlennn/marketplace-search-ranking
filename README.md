Пет-проект по задаче поискового ранжирования товаров маркетплейса на датасете WANDS.

## Задача

По поисковому запросу пользователя и каталогу товаров нужно было построить двухэтапную систему поиска: сначала отобрать кандидатов из полного каталога, затем переранжировать их по релевантности.
Для оценки отбора кандидатов использовал **Recall@K**, для итогового ранжирования — **NDCG@K**.

## Результат

* **Exact Recall@300:** `0.812630`
* **Exact + Partial Recall@300:** `0.665131`
* **Test NDCG@5:** `0.710994`
* **Test NDCG@10:** `0.717887`

NDCG рассчитывался по размеченным кандидатам, попавшим в Top-300 после первого этапа поиска.

## Решение

Разделил данные на train/validation/test по `query_id`, чтобы запросы не пересекались между выборками.

Для отбора кандидатов построил гибридный поиск: **BM25** по названиям товаров и семантический поиск по эмбеддингам `all-MiniLM-L6-v2`. Два списка объединял через **Reciprocal Rank Fusion**, после чего оставлял Top-300 кандидатов.

Для переранжирования собрал признаки лексической и семантической близости запроса и товара, а также признаки рейтинга и количества отзывов. Сложные отрицательные примеры выбирал среди `Irrelevant` товаров, которые сами попадали в Top-300.

Финальную модель построил на **LightGBMRanker** с objective **LambdaRank**.

## Стек

Python, pandas, NumPy, LightGBM, Sentence Transformers, rank-bm25, Matplotlib.
